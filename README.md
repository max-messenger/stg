STG — это мини-фреймворк на основе Dependency Injection Container (контейнера для внедрения зависимостей) [uber-go/fx](https://pkg.go.dev/go.uber.org/fx). Он позволяет быстро создавать и настраивать структуру микросервисов на основе готовых шаблонов

Фреймворк позволяет:

- Создавать микросервисы на основе шаблонов и запускать их
- Стандартизировать структуру и жизненный цикл сервисов
- Устранять дублирование кода и автоматически внедрять зависимости
- Разворачивать сервисы в инфраструктуре

## 1. Создание сервиса

Для создания сервиса из шаблона выполните команду:

```bash
./create.sh %имя_сервиса%
```

Каталог проекта будет создан на одном уровне с каталогом `stg`. Имя нового каталога совпадает с именем сервиса

### 1.2 Структура созданного сервиса

После генерации создаётся следующая структура каталогов и файлов:

```bash
%имя_сервиса%
├── cmd                              - каталог с точками входа
│   └── %имя_сервиса%
│       └── main.go                  - точка входа в приложение, парсинг флагов
├── config
│   ├── dockercompose                - набор конфигураций для Docker Compose
│   └── %имя_сервиса%
│       └── config.tmpl.yaml         - шаблон конфигурации приложения
├── docker-compose.yaml              - файл Docker Compose для локальной разработки
├── go.mod
├── go.sum
├── docs                             - Swagger-документация для API-сервиса
│   ├── docs.go
│   ├── fx.go
│   ├── provider.go
│   ├── gen.go
│   ├── swagger.json
│   └── swagger.yaml
├── pkg                              - набор модулей для работы приложения: HTTP, gRPC-сервер, сбор трассировок и метрик, логи, HTTP middleware, marshaler
│   ├── connections                  - набор модулей для подключения к различным базам данных и сервисам: Postgres, Redis Cluster, Kafka, gRPC
└── internal                         - исходники самого сервиса
    └── app                          - код приложения
        ├── app.go                   - создание приложения
        ├── config.go                - дополнительные конфигурации
        ├── fx.go                    - настройки модулей fx
        └── router                   - HTTP API сервиса
            ├── fx.go
            ├── response.go          - общие ответы для API
            └── router.go            - роутер API
```

Основные гайдлайны по разработке сервисов с использованием STG описаны в [файле guidelines/README](guidelines/README.md)

## 2. Создание приложения

Приложение создаётся через фабрику в файле `app.go`, которая возвращает объект `fx.App`. Менять в ней ничего не нужно

```go
func CreateApp(cfgName string) *fx.App {
    box := gibs.NewBox(
        Modules,
        gibs.WithAppName("%имя_сервиса%"),
        gibs.WithConfigFile(cfgName),
    )

    return box.CreateApp()
}
```

Модули добавляются в файле `fx.go`.

### 2.1 Пример структуры приложения

Пример структуры каталога `internal/app` приложения TODOLIST, содержащего код приложения и настройки модулей `fx`:

```bash
internal/app
├── clients          - клиенты для работы с внешними сервисами (HTTP, gRPC, bots)
│   ├── maxbot       - клиент MAX: подключение к боту, получение и отправка сообщений
│   └── fx.go        - модули clients
├── domain           - доменные модели для общения между сервисами
├── repository
│   ├── staterepo    - репозиторий для хранения состояния пользователя
│   ├── todorepo     - репозиторий для хранения todo
│   └── fx.go        - модули repository
├── router           - HTTP API сервиса
│   ├── todolistctrl - контроллер для TODOLIST
│   └── webhookctrl  - контроллер для webhook, нужен для получения сообщений из бота в режиме webhook
├── services
│   ├── bot          - сервис для обработки сообщений из бота
│   ├── todolist     - сервис для работы с todo
│   └── fx.go        - модули services
└── subscriber       - подписки на события из бота, сюда можно добавлять свои подписки, например из Kafka
```

## 3. Описание и подключение модулей

### 3.1 Подключение модулей

Чтобы подключить модуль, добавьте его в список Modules в файле `internal/app/fx.go`:

```go
var Modules = fx.Options(
    //.....
    moduleName.Module, 
    //.....
)
```

### 3.2 Стандартные модули

По умолчанию в проекте используются следующие модули:

```go
var defaultModules = fx.Options(
    grace.Module, // Модуль для запуска приложения в фоне
    health.Module, // Модуль для проверки статуса приложения
    server.Module, // Модуль для запуска сервиса в HTTP
    info.Module, // Модуль для получения информации о приложении
    telemetry.Module, // Модуль для сбора метрик Prometheus, телеметрии OpenTelemetry и профилирования
)
```

Для проверки статуса приложения и сбора метрик отдельно запускается HTTP-сервис. По умолчанию он работает на порту `8082`

Пример стандартной конфигурации находится в каталоге `config/%имя_сервиса%`


### 3.3 Модули PKG

Каталог `pkg` содержит набор модулей для работы приложения: `HTTP`, `gRPC`-сервер, сбор трассировок и метрик, логи, `HTTP-middleware`, `marshaler`

> Код внутри `pkg` не модифицируется. Если требуются доработки, обратитесь к владельцу репозитория


- [`Background Tasker (bgtasker)`](pkg/bgtasker/README.md) — запуск фоновых задач в приложении
- [`Grace`](pkg/grace/README.md) — управление жизненным циклом сервисов с поддержкой `graceful shutdown`. Включён в шаблон проекта
- [`HTTP`](pkg/http/README.md) — модуль для работы с HTTP-сервисами, включающий набор промежуточных обработчиков (`middleware`) для запуска сервисов в `HTTP`
- [`Health`](pkg/health/README.md) — получение информации о состоянии приложения. Включён в шаблон проекта, эндпоинт `/health` доступен на системном HTTP-сервере
- [`Info`](pkg/info/README.md) — получение информации о приложении через `HTTP endpoint`. Включён в шаблон проекта, эндпоинт `/info` доступен на системном HTTP-сервере
- [`Telemetry`](pkg/telemetry/README.md) — отправка данных о прохождении запросов (трассировки) и готовые функции для сбора метрик. Включён в шаблон проекта
- [`Server`](pkg/server/README.md) — запуск сервисов в `HTTP` и `gRPC`. По умолчанию включены сервисы для обработки запросов информации о приложении и метрик. Включён в шаблон проекта
- [`RateLimiter`](pkg/ratelimiter/README.md) — лимитер на основе кеша и `Redis`. Подключается через `fx`
- [`Queue`](pkg/queue/README.md) — модуль очередей на основе `Redis Streams` (Redis версии 6.2 и выше) со следующими возможностями:
    - Бинарный `payload`
    - Настройки по именам очередей
    - Ограничение параллельной обработки
    - Восстановление необработанных сообщений
    - Метрики `Prometheus` и `OTel`-трейсинг

  Подключается через `rediscli.Module` и `queue.Module`. Приложение запускает обработчики сообщений из очереди в фоновом режиме через `grace.Service`

### 3.4 Модули подключений (Connections)

Каталог `connections` содержит набор модулей для подключения к различным базам данных и сервисам: `Postgres`, `Redis Cluster`, `Kafka`, `gRPC`

Все модули подключений реализованы через модель пулов: для каждого подключения предусмотрены отдельная конфигурация и объект клиента. Подключаются через `fx`:

- [gRPC Clients](pkg/connections/grpccli/README.md) — работа с `gRPC`-клиентами
- [Kafka](pkg/connections/kafka/README.md) — работа с `Kafka`
- [Redis](pkg/connections/rediscli/README.md) — работа с `Redis`
- [Postgres](pkg/connections/postgres/README.md) — работа с `Postgres`
- [MaxBot](pkg/connections/maxbot) — работа с MAX-ботами: получение и отправка сообщений
