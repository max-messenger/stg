# STG (Service Template Global)

STG - это мини-фреймворк основанный на Dependency Injection Container [uber-go/fx](https://pkg.go.dev/go.uber.org/fx).

Основные цели фреймворка:

- шаблонизация скелета микросервисов, быстрый запуск новых;
- стандартизация структуры сервисов;
- стандартизация жизненного цикла сервисов;
- избавленме от повторяющегося кода и прокидывания зависимостей.
- удобное развёртывание сервисов в инфраструктуре.

Для создания сервиса из шаблона выполните команду:

```bash
./create.sh %app_name%
```

Проект создастся на том же уровне файловой системы что и `stg`, новый каталог будет с тем же именем что и сервис.

Основные гайдлайны по разработке сервисов с использованием STG можно посмотреть в [guidelines](guidelines/README.md).

## Структура сервиса

На выходе после генерации получаем следующую структуру каталогов и файлов:

```bash
%app_name%
├── cmd                              - каталог с точками входа
│   └── %app_name%
│       └── main.go                  - точка входа в приложение, парсинг флагов
├── config
│   ├── dockercompose                - набор конфигов для docker-compose
│   └── %app_name%
│       └── config.tmpl.yaml         - темплейт конфига приложения
├── docker-compose.yaml              - docker-compose файл для локальной разработки
├── go.mod
├── go.sum
├── docs                             - Swagger документация для api сервиса
│   ├── docs.go
│   ├── fx.go
│   ├── provider.go
│   ├── gen.go
│   ├── swagger.json
│   └── swagger.yaml
├── pkg                              - Набор модулей для работы приложения, http, grpc сервер, сбор трейсов и метрик, логи, http middleware, marshaler.
│   ├── connections                  - Набор модулей для подключения к различным бд и сервисами, postgres, redis cluster, kafka, grpc
└── internal                         - исходники самого сервиса
    └── app                          - код приложения
        ├── app.go                   - создание приложения
        ├── config.go                - дополнительный конфиги
        ├── fx.go                    - настройки модулей fx
        └── router                   - HTTP API сервиса
            ├── fx.go
            ├── response.go          - общие ответы для API
            └── router.go            - роутер API
```

## Дефолтные модули

По умолчанию в проекте используются следующие модули:

```go
var defaultModules = fx.Options(
    grace.Module, // модуль для запуска приложения в фоне
    health.Module, // модуль для проверки статуса приложения
    server.Module, // модуль для запуска сервиса в http
    info.Module, // модуль для получения информации о приложении
    telemetry.Module, // модуль для получения метрик в prometheus и otel и профайлинг
)
```

Отдельно запускается http сервис для проверки статуса приложения, и сбора метрик, по умолчанию на порту `8082`.

Пример стандартного конфига находится в папке `config/%app_name%`.

Создание приложения происходи через фабрику в файле `app.go`, возращает объект `fx.App`
Менять ничего не надо, модули добавляютя в файле `fx.go`

```go
func CreateApp(cfgName string) *fx.App {
    box := gibs.NewBox(
        Modules,
        gibs.WithAppName("%app_name%"),
        gibs.WithConfigFile(cfgName),
    )

    return box.CreateApp()
}
```

## PKG

Набор модулей для работы приложения, http, grpc сервер, сбор трейсов и метрик, логи, http middleware, marshaler.
В `connections` набор модулей для подключения к различным бд и сервисами, postgres, redis cluster, kafka, grpc

Часть модулей включена по умолчанию в проект, другие модули нужно добавить в файле `internal/app/fx.go`

```go
var Modules = fx.Options(
    //.....
    moduleName.Module, 
    //.....
)
```

Модифицировать код внутри `pkg` не надо, если требуются доработки обращайтесь к мейнтейнеру.

### [Background Tasker(bgtasker)](pkg/bgtasker/README.md)

Модуль для запуска фоновых задачь в приложении

### [Grace](pkg/grace/README.md)

Модуль для управления жизненным циклом сервисов с поддержкой graceful shutdown.
Включён в шаблон проекта.

### [HTTP](pkg/http/README.md)

Модуль для работы с http сервисами, в основном это набор middleware для запуска сервисов в http.

### [Health](pkg/health/README.md)

Модуль для получения информации о состоянии приложения.
Включён в шаблон проекта, работает на системоном порту. `/health`

### [Info](pkg/info/README.md)

Модуль для получения информации о приложении через HTTP endpoint.
Включён в шаблон проекта, работает на системоном порту. `/info`

### [Telemetry](pkg/telemetry/README.md)

Модуль для настройки отправки трейсов, а также хелперов для сбора метрик.
Включён в шаблон проекта.

### [Server](pkg/server/README.md)

Модуль для запуска сервисов в http и grpc.
По умолчанию включены сервисы для обработки запросов информации о приложении и метрик.
Включён в шаблон проекта.

### [RateLimiter](pkg/ratelimiter/README.md)

Модуль для работы с лимитером на основе кеша и redis. Подключить можно через `fx`

### [Queue](pkg/queue/README.md)

Общая очередь на Redis Streams (Redis 6.2+): бинарный payload, настройки по именам
очередей, ограничение параллельной обработки и восстановление pending-сообщений.
Подключается через `rediscli.Module` и `queue.Module`; фоновые consumers запускает
приложение через `grace.Service`. Поддерживает метрики Prometheus и OTel-трейсинг.

### [Тестирование бота](guidelines/bot-testing.md)

Практика unit-тестов bot-сервиса:

- проверка `ProcessUpdate` по входным update и outbound-вызовам;
- использование `testkit/bot`;
- моки внешних зависимостей через `mockgen`.

### Connections

Набор модулей для работы с различными бд и сервисами, postgres, redis cluster, kafka, grpc

#### [GRPC Clients](pkg/connections/grpccli/README.md)

Реализованно через модель пулов, где для каждого коннекта свой конфиг и объект grpc клиента.
Модуль для работы с grpc клиентами. Подключить можно через `fx`

#### [Kafka](pkg/connections/kafka/README.md)

Реализованно через модель пулов, где для каждого коннекта свой конфиг.
Модуль для работы с kafka. Подключить можно через `fx`

#### [Redis](pkg/connections/rediscli/README.md)

Реализованно через модель пулов, где для каждого коннекта свой конфиг и объект universal redis клиента.
Модуль для работы с redis. Подключить можно через `fx`

#### [Postgres](pkg/connections/postgres/README.md)

Реализованно через модель пулов, где для каждого коннекта свой конфиг и объект postgres клиента.
Модуль для работы с postgres. Подключить можно через `fx`
