## Goal

Turn a feature request into the smallest complete, testable vertical slice,
adding only the domain, service, repository, client, infrastructure, and HTTP
layers the behavior requires.

## Discovery And Plan

1. Read `AGENTS.md` and inspect the relevant domain, services, repositories,
   clients, router, configuration, migrations, tests, and Fx composition. Inspect
   local `pkg/` APIs instead of importing external GIBS packages. In an app
   generated by `create.sh`, inspect the resulting tree rather than assuming
   example components survived generation.
2. Trace behavior from the entry point to dependencies. State a concise plan
   naming files, owning context, data flow, errors, Fx changes, configuration or
   migrations, tests, and verification commands.
3. Add layers only when their responsibility is present:
   - `domain` holds shared business models and expected business errors.
   - A focused service owns business rules and consumer-owned interfaces.
   - A repository exists for direct persistence access by its owning service.
   - A client talks to an external system; local technical capabilities belong
     in infrastructure packages.
   - A controller under `router/<feature>ctrl` provides a public HTTP entry point.
4. Ask for confirmation before incompatible public HTTP changes, schema changes,
   deploy/public configuration changes, MAX webhook subscription changes, or
   changes across independent subsystems. Otherwise implement the minimal plan.

## Implementation

1. Apply baseline conventions in `AGENTS.md`.
2. For HTTP endpoints, apply `stg-add-http-endpoint`; for persistence, apply
   `stg-add-repository`.
3. Add layers, configuration, migrations, and background work only as required.
4. For MAX behavior, inspect the existing subscriber-to-bot dispatch. Preserve
   one update-stream consumer, use local consumer-owned interfaces, and ensure
   bounded workers and shutdown when changing dispatch. Add a multiplexer only
   if multiple services need update routing.

## Completion

1. Run applicable generation and verification from `AGENTS.md`, including
   focused package tests if framework or test helpers changed.
2. Report delivered behavior, ownership, contract/config/schema changes,
   commands run, and verification gaps.
